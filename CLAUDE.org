** Guidance for AI/LLM Editing Sessions
- *Don't ask, just do*: When Jay provides a file path, READ IT FIRST before asking questions. If he says "here's an error" or "look at this" with a path, just read the file—don't ask what it is or request more context.
- When touching any literate Org file (e.g., =pasteboard-copy-and-paste-functions.org=), delete the stale tangled =.el=, retangle immediately, and run =emacs --batch <file.el> --eval '(check-parens)'= before restarting.
- When changing LaTeX class/template files in [[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/][latex-templates/]], remember that Org/LaTeX class definitions can stay cached in the live Emacs session. After editing a template, reload the classes with =M-x jay-load-latex= or restart Emacs before treating the next export as a real test.
- *LaTeX hyphenation preference*: Jay dislikes hyphenation in prose output and rejected ragged-right bullets after trying them. Prose classes inherit a hyphenation-averse baseline from [[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/jay-latex-prose-defaults.el][latex-templates/jay-latex-prose-defaults.el]] — currently just =\righthyphenmin=5= (widow/club penalties and =\emergencystretch=3em= are also there; nothing else). Full debugging post-mortem, empirical test matrix, and the fast-test protocol for adding a new knob live in [[file+emacs:/Users/jay/emacs/emacs-settings/docs/codebase-wisdom.org][docs/codebase-wisdom.org]] under /TeX Hyphenation Knobs: Theoretical Clean Can Lose to Empirical Badness/ (2026-04-23). The short rule: *test any proposed hyphenation knob empirically against the real proposal in the real class before committing* — theoretical TeX solutions (e.g. =\finalhyphendemerits=) routinely fail in Garamond + tight enumitem measures because alternative-break =badness²= demerits dominate. Traps to avoid (don't suggest): =\sloppy=, document-wide =\hyphenpenalty=10000=, =\pretolerance=10000=, document-wide or unscoped =\RaggedRight= (rejected aesthetically), =\exhyphenpenalty=10000= (blocks explicit-hyphen breaks like "well-known"). Anything added to =jay/latex-prose-defaults= must also be captured in =jay/latex-prose-default-legacy-blocks= so the strip-then-reinsert helper stays idempotent.
- Special case: for [[file+emacs:/Users/jay/emacs/emacs-settings/spacecraft-mode.org][spacecraft-mode.org]] and [[file+emacs:/Users/jay/emacs/emacs-settings/gnu-emacs-startup.org][gnu-emacs-startup.org]], batch tangling should pass the explicit output file path (to [[file+emacs:/Users/jay/emacs/emacs-settings/spacecraft-mode.el][spacecraft-mode.el]] or [[file+emacs:/Users/jay/emacs/emacs-settings/gnu-emacs-startup.el][gnu-emacs-startup.el]]). A bare =org-babel-tangle-file= can misleadingly report =0 code blocks= for those files.
- Treat regex tweaks with extra caution: smoke-test them in a scratch buffer (=re-search-forward=) to avoid =invalid-regexp= surprises.
- Keep the edit loop tight—edit → tangle → =check-parens= (or byte-compile)—to catch structural errors before they reach Spacemacs startup.
- *Test runtime behavior instead of theorizing*: When uncertain whether a keybinding, function, package, or config setting actually works at runtime, do not speculate — ask Jay to test it, or run a direct safe test yourself if appropriate.
- *Config analysis is not runtime proof*: Static config inspection tells you what should happen, not what does happen. Autoloads, stale installs, indirect loading, compatibility shims, and cached state can all keep something working even when the config looks contradictory.

- *For keybinding questions, ask for the shortest live check*: If the real question is "does this binding still work?", ask Jay to press the binding and report the result before recommending cleanup or replacement.
