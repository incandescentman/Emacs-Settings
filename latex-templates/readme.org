#+TITLE: LaTeX Templates Documentation

* Header Configuration

Templates that use =fancyhdr= (e.g., =elegant-garamond=, =elegant-helvetica=) define =\leftheader= and =\leftheaderurl=. For =elegant-garamond= and =elegant-garamond-tabularray=, if you omit =\leftheader{...}= the top-left page header falls back to the document title. Add =\leftheaderurl{...}= only when you want that left header text linked:

#+begin_example
#+LATEX_HEADER: \leftheader{Jay Dixit}
#+LATEX_HEADER: \leftheaderurl{https://storytelling.nyc}
#+end_example

If you do set =\leftheader{...}=, it overrides the title fallback completely.

When the title fallback is in effect, only =#+TITLE:= appears in the left header. A =#+SUBTITLE:= on the document is preserved on the title page itself but stripped out of the running header.

The right header (=\rhead=) auto-populates from the current section or subsection title. Subsubsections do not replace it.

* Table of Contents and Numbering

For Org files that need a LaTeX table of contents without visible section numbers, use:

#+begin_example
#+OPTIONS: H:5 num:t toc:t
#+LATEX_HEADER: \setcounter{secnumdepth}{0}
#+LATEX_HEADER: \setcounter{tocdepth}{3}
#+end_example

The =num:t= setting is intentional: Org emits normal =\section{...}= commands that populate the LaTeX =.toc= file. =\setcounter{secnumdepth}{0}= suppresses the printed numbers. If you use =num:nil= instead, Org emits starred headings such as =\section*=, and the table of contents will be empty unless the document adds custom =\addcontentsline= handling.

* Footer Configuration

For =elegant-garamond= and =elegant-garamond-tabularray=, the footer logo is also configurable per document. The template keeps the old Storytelling NYC image as the default, but you can override it and pair it with a different company name in the header:

#+begin_example
#+LATEX_CLASS: elegant-garamond
#+LATEX_HEADER: \footerlogo{/Users/jay/Dropbox/github/astro-monorepo/apps/socratic/src/assets/images/socratic-ai-complex-logo-transparent_color.png}
#+LATEX_HEADER: \EnableLogoFooter
#+end_example

If you omit =\EnableLogoFooter=, the template falls back to a centered page number. If you use =\DisableFooter=, it suppresses the footer entirely. In the Garamond templates, the footer is also suppressed automatically on the first and last page.

You can also add footer text beside the logo:

#+begin_example
#+LATEX_CLASS: elegant-garamond
#+LATEX_HEADER: \leftheader{Storytelling NYC}
#+LATEX_HEADER: \leftheaderurl{https://storytelling.nyc}
#+LATEX_HEADER: \footerbrand{Storytelling NYC}
#+LATEX_HEADER: \EnableLogoFooter
#+end_example

If =\footerbrand= is empty, the footer stays image-only. If it is set, the template renders the logo with a darker-grey condensed bold brand wordmark beside it.

* Invoice Letterhead Branding

The invoice-with-letterhead templates let you override the header wordmark and header logo per document without editing the template file:

#+begin_example
#+LATEX_CLASS: blue-invoice-letterhead
#+LATEX_HEADER: \letterheadbrand{SOCRATIC AI}
#+LATEX_HEADER: \letterheadlogo{/Users/jay/Dropbox/github/astro-monorepo/apps/socratic/src/assets/images/socratic-ai-complex-logo-transparent_color.png}
#+end_example

The defaults stay the same if you omit that header line:
- [[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/blue-invoice-letterhead-storytelling-nyc.el][📄 blue-invoice-letterhead-storytelling-nyc.el]] defaults to =STORYTELLING.NYC=
- [[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/blue-invoice-letterhead-sunjay-e-dixit.el][📄 blue-invoice-letterhead-sunjay-e-dixit.el]] defaults to =SUNJAY E. DIXIT=
- [[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/blue-invoice-letterhead-socratic-ai.el][📄 blue-invoice-letterhead-socratic-ai.el]] defaults to =SOCRATIC AI= and the Socratic AI icon. Not loaded by default in =org-export.el=; =require= it manually when needed, or use the per-document =\letterheadbrand= / =\letterheadlogo= override above with the default loaded class.

Invoice letterhead headers are separate from the configurable footer logo system above. For invoice-logo failures, inspect the invoice class's =\fancyhead[C]= block and =\letterheadlogo= value. * Thought Leadership Playbook Templates

The thought-leadership countdown has two independent classes built on the Garamond export system:

- =thought-leadership-playbook= ([[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/thought-leadership-playbook.el][📄 thought-leadership-playbook.el]]) is the blue, poster-like version with a dedicated cover page and one major phase per page.
- =thought-leadership-playbook-warm= ([[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/thought-leadership-playbook-warm.el][📄 thought-leadership-playbook-warm.el]]) is the warm editorial version derived from the Claude Design reference: margin checkboxes beside filled date chips, atomic left-bar milestone callouts, a six-stat August floor ledger, an oxblood-accented booktabs recurring-week grid, compact phase chronology, a seven-page print sequence, and side-by-side slip/deferred columns.

Both classes understand the same semantic layout commands, so one Org source can switch designs by changing only its =#+LaTeX_CLASS:= line. The source may use =\PlaybookPhaseBreak=, =\PlaybookContinuationBreak=, =\PlaybookMonthBreak=, =\PlaybookEngineBreak=, =\PlaybookTableHead=, and the three =\PlaybookBackmatter...= commands without embedding a palette or hard-coded page layout.

The warm class also accepts a separate title that does not affect the blue cover:

#+begin_example
#+LATEX_HEADER: \PlaybookCoverTitle{Thought Leadership Countdown}
#+LATEX_HEADER: \PlaybookWarmTitle{Thought Leadership Countdown \& Launch Plan}
#+end_example
