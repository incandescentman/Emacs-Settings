* Overview

The goals tooling is split into two modules that work together:

1. *Workflow Automation Module* ([[file+emacs:/Users/jay/emacs/emacs-settings/jay-org-roam-suite/jay-org-roam-core.el][jay-org-roam-core.el]])
   - Prefix: =s-u=
   - Purpose: get you into action quickly (start day, anti-stall, revenue block)

2. *Rep Counter Module* ([[file+emacs:/Users/jay/emacs/emacs-settings/jay-goals-system.el][jay-goals-system.el]])
   - Prefix: =s-M-g=
   - Purpose: show weekly intentions in the mode line and track weekly input metrics in [[file+emacs:/Users/jay/Dropbox/roam/velocity/tracking/weekly-reps.org][weekly-reps.org]]

Note: =s-g= remains =isearch-repeat-forward=.

* Getting Started (2 Minutes)

If you're at your desk and want to start work immediately, do this sequence:

1. Press =s-u g= (=jay/goals-start-day=)
   - Opens daily note + execution dashboard + goals hub
   - Ensures your Daily Pipeline exists
2. Fill only these first:
   - OBT
   - MIT 1
   - Reach-out 1
3. Press =s-u R= (=jay/revenue-block-start=)
   - Starts =prolific= sprint engine (default: 3 sprints ~= 90 min)
4. Start work on OBT immediately
5. As reps happen, log them with =s-M-g 1/2/3/4=

If stuck for >3 minutes at any point, press =s-u A=.

* Daily Execution Checklist

** Morning (5 minutes)
- [ ] Run =s-u g=
- [ ] Set OBT + MIT 1 + MIT 2
- [ ] Choose first outreach action
- [ ] Start focus block: =s-u R=

** During Work
- [ ] Stay on Track 1 first (revenue before craft)
- [ ] Log reps as you complete them (=s-M-g 1/2/3/4=)
- [ ] If blocked: run anti-stall (=s-u A=)
- [ ] If interrupted hard: stop block (=s-u C-r=), then restart later (=s-u R=)

** Evening (5 minutes)
- [ ] Quick scoreboard check: =s-M-g s=
- [ ] Ensure today's reps were logged
- [ ] Decide tomorrow's first move (OBT starter step)

* Minimum Viable Day (When Overloaded)

If the day is chaotic, do this minimum set:

1. =s-u g=
2. One 30-90 min focused block (=s-u R=)
3. One outreach rep (=s-M-g 1=)
4. One follow-up rep (=s-M-g 2=)
5. If frozen, one anti-stall sprint (=s-u A=)

This keeps momentum and protects the system on hard days.

* Workflow Automation (=s-u=)

These commands live in [[file+emacs:/Users/jay/emacs/emacs-settings/jay-org-roam-suite/jay-org-roam-core.el][jay-org-roam-core.el]].

** Mode-line intentions

The mode line reads [[file+emacs:/Users/jay/Dropbox/roam/velocity/goals/20261113191152-weekly-intentions.org][Weekly Intentions]]. Compact labels appear together; hovering shows the full wording. Saving the file in Emacs refreshes the display immediately; external edits appear within five minutes. Rep commands remain separate.

** How to update weekly intentions

Follow [[file+emacs:/Users/jay/Dropbox/roam/velocity/goals/20261113191152-weekly-intentions.org::*How to review weekly intentions][the private review procedure]] for agent interactions. Keep personal content and review triggers in that private file, not in this repository.

Under ~* Current intentions~, each level-two heading is a compact mode-line label; its body contains the full wording, including nested bullets. Only that subtree is displayed. Previous versions belong under ~* History~ with their review dates and appropriately nested headings.

Update ~#+REVIEWED: YYYY-MM-DD~ only after an explicit change or reaffirmation. Opening the file, editing labels, or displaying a prompt does not reset the date. Use the actual local review date.

More than seven calendar days after ~REVIEWED~ means day eight onward. Emacs prompts at most once per local calendar day, including across restarts. It checks after sixty seconds idle, with focus and no active minibuffer, and shows a nonblocking review buffer. The existing intentions stay visible until updated. Reminders operate while Emacs is running.

The last-prompt date is stored in [[file+emacs:/Users/jay/.emacs.d/weekly-intentions-last-prompt.txt][the prompt-date file]]. Its live path is ~jay-goals-intentions-prompt-file~; agents share this record to avoid duplicate daily reminders.

Use ~M-x jay-goals-review-intentions~ to open the review. ~M-x jay-goals-confirm-intentions~ explicitly reaffirms the saved intentions and refuses to overwrite an unsaved or externally changed visiting buffer. ~jay-goals--update-mode-line~ refreshes after external edits; otherwise those edits appear within five minutes. Saving the source in Emacs refreshes immediately.

** Implementation references

Documented capability: [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Idle-Timers.html][Emacs idle timers]] run after inactivity; [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Displaying-Buffers.html][display-buffer]] can show a buffer without selecting it. The implementation uses these existing primitives rather than adding a scheduler. Practitioner context: [[https://doc.norang.ca/org-mode.html#WeeklyReviewProcess][Bernt Hansen's weekly review]] uses an explicit Org review routine. The eight-day threshold and once-daily reminder are configured behavior, not claims from that source.

* Use Cases (What To Do When)

| Situation | Do this |
|-----------+---------|
| “I don't know where to start” | =s-u g=, then do OBT for 10 minutes |
| “I keep avoiding this task” | =s-u A= and do the smallest action |
| “I need deep focus right now” | =s-u R= and commit to first 25 minutes |
| “How am I doing this week?” | =s-M-g s= (quick) or =s-M-g S= (full file) |
| “I got interrupted badly” | =s-u C-r=, handle interruption, restart with =s-u R= |

* Suggested Weekly Rhythm

1. Monday: check baseline with =s-M-g s=
2. Daily: log reps as they happen (don't batch at end of week)
3. Friday review: =s-M-g S= and compare inputs vs outcomes
4. New week reset only if needed: =s-M-g r=
