#+TITLE: Pasteboard Architecture
#+DATE: 2025-09-24
#+DESCRIPTION: Deep dive into the macOS pasteboard helpers that back clean pasting.

* Overview
- Copy entry points: `pasteboard-copy-adaptive`, `pasteboard-copy-verbatim`, and `pasteboard-copy-and-replace-em-dashes-in-clipboard` (default text-mode cleaner).
- Paste entry points: `pasteboard-paste`, `pasteboard-paste-clean`, `pasteboard-paste-verbatim` (`pasteboard-paste-raw` alias), and `pasteboard-paste-adjusted-subtrees`.
- Goal: Move text from macOS apps into Org buffers while normalizing typography, Markdown, and Org semantics.

* Evolution History
- Early version just called `shell-command-on-region` with `pbpaste`.
- Added multi-stage cleaners (`replace-smart-quotes`, markdown converters) to support blogging and knowledge-base workflows.
- 2025-09-24 regression fix: table separator protection via smarter `normalize-dashes`.
- 2025-09-24 regression fix: emoji joiner preservation inside `replace-weird-spaces`.
- 2025-10-05 critical fix: markdown bold `**text**` → org bold `*text*` conversion order and heading detection.
- 2025-10-10 critical fix: `pasteboard--demote-headings-in-string` regex pattern fixed to only match actual headings (with space after stars), not bold text at line start.
- 2025-11-02 improvement: added dedicated Markdown table separator tightening and defaulted `fundamental-mode` pastes to verbatim.
- 2026-05-19 critical fix: `pasteboard-paste-adaptive` was rewriting top-level `* Heading` lines to `- Heading` whenever the clipboard text also contained any `-` bullets. Two compounding bugs: (a) `pasteboard--analyse-clipboard-text` only scored `\\*\\{2,\\}` (two-or-more-star) lines as Org, so single-star Org headings contributed nothing to `org-score`, letting `md-score` win on any text that mixed `*` headings with `-` bullets; (b) the "fallback" coercion loop in `pasteboard--clean-string` unconditionally rewrote every `^\\* ` line to `- ` once the style was `markdown`, ignoring the neighbor-aware `pasteboard--should-convert-asterisk-line` heuristic that the primary converter respects. Fix: the analyser now classifies each top-level single-`*` line by its non-blank neighbors (paragraph-text neighbors → Org signal; list neighbors → bullet count), and the fallback loop now calls `pasteboard--should-convert-asterisk-line` per match so heading-like single-`*` lines are protected even when scoring still picks `markdown`.
- 2026-06-30 improvement: `replace-smart-quotes` now normalizes OCR/PDF form-feed page breaks (`\f`) to a plain space through =smart-quotes-replacement-pairs=. Use a space rather than deleting the character so pasted prose cannot accidentally join adjacent words.

* Current Implementation Details

** Text Cleaning Pipeline
`pasteboard--clean-string` processes text in this order (ORDER MATTERS):
  1. `convert-markdown-headings-to-org` - MUST run first before asterisk processing
  2. `replace-smart-quotes` - Converts markdown bold `**` → org bold `*`, smart quotes, and OCR/PDF form feeds.
  3. `replace-smart-quotes-regexp`
  4. `replace-weird-spaces`
  5. `pasteboard--strip-cite-markers`
  6. `convert-markdown-blockquotes-to-org` (strips `>` markers from single- and multi-line blockquotes, preserving blank lines)
  7. `convert-markdown-links-to-org-mode`
  8. Markdown-only cleanup (when detected as Markdown): convert inline emphasis if enabled, convert asterisk bullets to dashes while skipping heading markers, fallback bullet conversion, tighten markdown table separators, run `normalize-dashes` if available, convert Markdown fences to org src blocks if available
  9. `pasteboard--strip-trailing-whitespace`
  10. `pasteboard--ensure-blank-line-before-headings`
  11. `pasteboard--convert-bold-to-headings`
  12. `pasteboard--remove-blank-line-after-headings` (preserves blank lines before headings and `#` directives)
  13. `pasteboard--remove-redundant-heading-asterisks` (removes trailing whitespace-separated `*` from headings)

** One Obvious Clean Path
- Principle: keep exactly one clean insertion path for predictability and ease of maintenance.
- Canonical entry point: `pasteboard-paste-clean`.
- `pasteboard-paste-adaptive` delegates all non-verbatim clean branches to `pasteboard-paste-clean` instead of manually re-implementing cleanup steps.

** Adaptive Paste Decision Tree
`pasteboard-paste-adaptive` chooses paste behavior based on context (see =pasteboard-copy-and-paste-functions.el=):

*** 1. URL + Active Region → Bracket Link
- If clipboard contains URL (`https://` or `www.`) AND region is active
- Creates org bracket link: `[[url][selected text]]`
- Most specific check, evaluated first

*** 2. Code Modes → Verbatim
Paste without cleaning in:
- Shell mode (`sh-mode`)
- Emacs Lisp mode (`emacs-lisp-mode`)
- Markdown mode (`markdown-mode`, `gfm-mode`)
- Web mode (`web-mode`)
- Fundamental mode (`fundamental-mode`) for scratch/plain buffers

*** 3. Text Modes → Clean + Optional Demotion
In org-mode (without `org-config-files-local-mode`) or `text-mode`:
- Delegate to `pasteboard-paste-clean` (canonical clean path)
- `pasteboard-paste-clean` applies `pasteboard--clean-string` transformations
- If in org-roam buffer AND text starts with heading: also demote headings
- Otherwise: just cleaned text

*** 4. Heuristic Fallback
For unmatched modes, inspect characters around point:
- If prev/next char is punctuation (`:`, `'`, `(`, `|`, `[`, `/`, `\`, `"`, `=`, `<`, `>`, `{`, `}`):
  - Paste verbatim (assume code/structured context)
- Otherwise:
  - Delegate to `pasteboard-paste-clean` for cleaned insertion

** Other Implementation Notes
- `normalize-dashes` (in `shared-functions`) now skips lines that look like Markdown tables.
- `pasteboard--tighten-markdown-table-separators` collapses separator rows (`| --- |`) into Org-compliant `|---|` before dash normalization runs.
- Form-feed page breaks from OCR/PDF text are normalized to one plain space in [[file+emacs:/Users/jay/emacs/emacs-settings/pasteboard-copy-and-paste-functions.el][pasteboard-copy-and-paste-functions.el]]. This prevents Emacs redisplay trouble while preserving word separation. Removing the page-number lines that often follow form feeds is a separate regex cleanup and is not handled by =smart-quotes-replacement-pairs=.
- Raw helpers wrap `pbpaste` with `perl -p -e 's/\r$//'` and `tr` to remove carriage returns.

* Org-Roam Specific Behavior

When `pasteboard-paste-adaptive` detects an org-roam buffer (by checking for `:ID:` property at buffer start), it applies an additional transformation to maintain proper heading hierarchy:

** Detection
- Function: `is-org-roam-buffer-p()` (in =pasteboard-copy-and-paste-functions.el=)
- Checks if buffer is in `org-mode`
- Looks for pattern: `^:PROPERTIES:\n:ID: ...\n:END:` at beginning of file

** Demotion Behavior
When pasting into an org-roam buffer AND the cleaned text contains org headings:
- All headings are automatically demoted by one level
- Function: `pasteboard--demote-headings-in-string` (in =pasteboard-copy-and-paste-functions.el=)
- Pattern: `^\\(\\*+\\) ` (note the required space after asterisks)
- Transformation: `** Heading` → `*** Heading`

** Purpose
Org-roam notes typically have a single top-level structure. When pasting external content with headings, automatically demoting them ensures they become sub-headings rather than competing with the note's main structure.

** Example Flow
#+BEGIN_EXAMPLE
Clipboard (markdown):
## Resources
### Books
**"How to Take Smart Notes"** by Sönke Ahrens

Regular org-mode paste:
** Resources
*** Books
*"How to Take Smart Notes"* by Sönke Ahrens

Org-roam paste (demoted):
*** Resources
**** Books
*"How to Take Smart Notes"* by Sönke Ahrens
#+END_EXAMPLE

** Critical Implementation Detail
The demotion regex MUST include the space after asterisks: `^\\(\\*+\\) `

- ✓ Correct: Only matches actual org headings like `** Heading`
- ✗ Wrong: `^\\(\\*+\\)` would also match bold text like `*bold*` at line start

This distinction prevents bold text at the beginning of lines from being incorrectly demoted (the 2025-10-10 bug fix).

* Performance and Reliability Considerations
- Cleaning runs in-buffer; large pastes pay the cost per regex pass—acceptable for short articles but consider profiling if >5k lines.
- Use markers to avoid mis-calculating the end point when cleaners change text length.
- Failure cases usually stem from outside dependencies (`pbpaste`, shell pipeline). Keep Terminal permissions granted under System Preferences → Security & Privacy → Accessibility.

* Critical Distinctions: Markdown Bold vs Org Headings

** The Desiderata
When processing text that could be markdown or org-mode, the system MUST distinguish between:
- **Markdown bold text**: `**The Future Is Now**` - text surrounded by double asterisks
- **Org headings**: `** Heading Text` - asterisks followed by SPACE then text
- **Org bold text**: `*The Future Is Now*` - text surrounded by single asterisks

** Expected Behavior
Given this markdown input:
#+BEGIN_EXAMPLE
**The Future Is Now**

When we think about the future...
#+END_EXAMPLE

The system MUST:
1. Convert `**The Future Is Now**` → `*The Future Is Now*` (markdown bold to org bold)
2. NOT treat it as an org heading (even though it starts with `**`)
3. NOT demote it when in org-roam buffers
4. Result in: `*The Future Is Now*` as bold text, not a heading

** Implementation Requirements
All functions that detect org headings MUST use the pattern `^\\*+ ` (with space) not just `^\\*+`:
- ✓ Correct: `(re-search-forward "^\\(\\*+\\) " ...)` - only matches actual headings
- ✗ Wrong: `(re-search-forward "^\\(\\*+\\)" ...)` - incorrectly matches bold text at line start

** Test Cases
The pasteboard system must handle these correctly:
| Input (Markdown)           | Output (Org)              | Type           |
|---------------------------+---------------------------+----------------|
| `## Heading`              | `** Heading`              | Heading        |
| `## **Bold Heading**`     | `** *Bold Heading*`       | Heading + Bold |
| `**Bold at line start**`  | `*Bold at line start*`    | Bold only      |
| `Regular **bold** text`   | `Regular *bold* text`     | Inline bold    |

* Markdown Detection Heuristics

** Goal
Detect when clipboard text is Markdown using `* ` for unordered lists, convert to hyphens (`- `) for Org buffers, while preserving genuine Org headings.

** Detection Logic
=pasteboard--analyse-clipboard-text= scores signals:
- *Markdown signals*: `^#` headings, `-` / `+` bullets, ordered lists, blockquotes, fenced code, inline links, `**bold**`. Single-`*` bullets are NOT scored directly here — they are classified separately (see below).
- *Org signals*: `#+` directives, TODO keywords, property drawers, multi-star headings (`\\*\\{2,\\}`), `SCHEDULED:` / `DEADLINE:` markers.

After the regex-driven scoring, the analyser walks every top-level `^\\* ` line and classifies it by neighbor context (using `pasteboard--neighbor-nonblank-kind`):
- Indented OR list-neighbored → counted as `asterisk-bullets` (markdown-bullet-like).
- Surrounded by paragraph text or other Org headings → scored as `org-score += 1` (single-star Org heading).

Style selection (cascade in order):
1. =md-score >= org-score + 2= → Markdown
2. =org-score >= md-score + 2= → Org
3. =md-score >= 3= and =org-score = 0= → Markdown
4. =md-score = 0= and =org-score > 0= → Org
5. =asterisk-bullets >= 3= and =org-score = 0= → Markdown (catches plain `* a / * b / * c` bullet lists)
6. Otherwise → =nil= (ambiguous — skip the markdown→org transforms)

Override: if =pasteboard--text-contains-markdown-headings-p= matches any =##=–=######= heading in the text, the style is *forced* to markdown regardless of scoring.

** Conversion Workflow
1. Headings convert first (=convert-markdown-headings-to-org=)
2. Smart quotes, weird-space cleanup, blockquotes, links
3. If style is markdown: =pasteboard--convert-asterisk-bullets-to-dashes=, which calls =pasteboard--should-convert-asterisk-line= per match (indent>0 → convert; indent=0 → convert only when a non-blank neighbor is list-like).
4. Fallback sweep for any `^\\* ` lines that slipped through — but the fallback now also calls =pasteboard--should-convert-asterisk-line=, so heading-like single-`*` lines (text neighbors) are preserved even if step 3 missed them.
