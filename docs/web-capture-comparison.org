* Decision and current behavior
Keep org-web-tools for the Emacs integration and use Defuddle for article extraction, followed by Pandoc and the existing Org cleanup. Defuddle won the Strobist comparison after paragraph normalization: it retained David Hobby's headshot, which Mozilla Readability removed, and produced the same Lighting 101 body as Readability after cleanup.

The expanded comparison exposed losses in Defuddle's default filters too. The selected configuration disables small-image removal, low-score removal, content-pattern removal, and exact/partial selector removal. Those settings recovered the Photography Life chapter list, the Substack embedded cards, and recipe equipment. A small adapter restores an enclosing image link when Defuddle keeps the image but drops that link. No missing article text fragments or source hrefs remained in the selected HTML for the five downloaded article samples. This is evidence for this corpus, not a guarantee for every page.

The tradeoff is more peripheral clutter, especially on TIFF and the recipe page. The original comparison left styled Strobist section labels as ordinary text because they were not source HTML headings. Updated 2026-10-26: the helper now promotes standalone legacy font-size titles before Defuddle strips their sizing; the 100-page Strobist check retained all 272 non-navigation styled titles.

Updated after the PDF review on 2026-10-26: when a retained image links directly to an original image file, the helper requests only bytes 0–65535 and checks the image response and its resolution metadata with ExifTool. It requires a valid HTTP 206 range response and caps the bytes read at 64 KiB. Servers that ignore Range have their response canceled without reading the body. An original declaring under 10 DPI on either axis, after physical-unit conversion, keeps the displayed image; unitless aspect ratios are not DPI. Failed requests, HTML viewers, missing ExifTool, metadata errors or warnings, and timeouts also keep the displayed image. A partial non-JPEG file is not upgraded because its metadata may occur later in the file. Emacs downloads a selected original normally. Links to articles remain unchanged, and the helper never invents higher-resolution URLs. Retained YouTube and Vimeo iframes and HTML video elements become clickable links before Pandoc, which otherwise drops embeds. This applies to the Defuddle path; the EWW fallback retains its existing extraction behavior.

The follow-up check preserved the text and image counts of all 100 Strobist source pages and restored five video links through Pandoc. Seven Node regression tests now cover video links, original-image selection, article links, unavailable or non-image originals, low DPI, physical units, ignored ranges, and a real 64 KiB prefix from a 240-DPI original; run ~node --test /Users/jay/emacs/emacs-settings/scripts/web-capture/extract.test.mjs~. The live Emacs capture path preserved the Joker video's link and verified both keeping a 2-DPI thumbnail and upgrading a 240-DPI original. Strobist-specific navigation removal, contents depth, portrait sizing, and repairs to five images with bad resolution metadata were made in the note, not added to the capture command or template. The later approved resolution guard prevents selecting similarly broken originals in future captures; it does not modify images.

The command now merges repeated prose line breaks into paragraph boundaries and preserves single caption breaks. C-u before either clean capture command prompts for a URL override. Updated 2026-11-23: a capture is inserted at the cursor on a blank line, or immediately after the whole current nonempty line. Heading depth is computed separately: use the enclosing captured page’s level, or a child level in an ordinary section. Following text stays in place; without a separating heading, Org treats it as part of the capture’s last heading. The cursor finishes immediately after the inserted text, before a blank separator if another heading follows. Standalone break lines are normalized as paragraph boundaries. If Node or the extraction helper fails, the command reports the diagnostic and uses EWW on the same downloaded page. HTTP failures still stop with the attempted URL and reason; the command never switches to the clipboard after a failed fetch. Pandoc and Lisp errors retain their original diagnostics.

Install dependencies on another machine: ~npm ci --prefix /Users/jay/emacs/emacs-settings/scripts/web-capture~ and ~brew install exiftool~. ExifTool must be on Emacs's PATH for original-image upgrades; otherwise the displayed images remain in use.

The Emacs commands and their helpers live in [[file+emacs:/Users/jay/emacs/emacs-settings/web-capture.org][web-capture.org]], which tangles to [[file+emacs:/Users/jay/emacs/emacs-settings/web-capture.el][web-capture.el]]. The startup loader loads it immediately after Shared Functions; ~s-P~ still runs ~jay/org-web-tools-insert-web-page-as-entry-clean~. The capture tests load the complete module directly. Export settings and remote-resource trust remain outside it.

* Reusable link and interface cleanup, 2026-11-23
The adapter now restores meaningful HTTP(S) links that Defuddle strips from headings, using exact source text and unambiguous link ranges. It removes the exact new-window accessibility annotation only from recognized screen-reader spans inside links, and removes explicitly decorative SVG/data-image icons only from links that already have readable labels. This prevents encoded social-icon junk before Pandoc without deleting hidden course descriptions or flattening source heading levels. The EWW fallback is unchanged. See [[file+emacs:/Users/jay/emacs/emacs-settings/docs/web-capture-improvements.org][the implementation and verification record]] for the source comparisons, limitations, and tests.

* Capture fixes versus document cleanup
Fix recurring capture problems in the tool. Handle unusual, document-specific cleanup manually or with an agent. For example, preserving embedded videos belongs in the capture command; removing Strobist's uncommon ~COMING NEXT~ lines belongs in the individual note. Consider agent-assisted cleanup before adding permanent rules for an isolated page detail. This is Jay's approved scope decision, recorded 2026-10-26.

* Browser capture is a separate decision
Chrome already allowed JavaScript from Apple Events; no setting was changed. On Lighting 101, downloaded HTML and Chrome's DOM produced identical article outputs with Readability and Defuddle. TIFF demonstrates a benefit of browser capture: Chrome returned real content where a fresh request returned a challenge.

The open ChatGPT page explicitly contained “Loading older messages…”. Its captured main DOM was therefore not proof of a complete conversation. Both article extractors also discarded parts of the text that was loaded. Browser DOM capture is not integrated into the command, and ChatGPT still receives the explicit copy-text/html2org-clipboard advice after a fetch failure. A dedicated conversation exporter needs a separate completeness test.

* Existing Emacs packages
[[https://github.com/alphapapa/org-web-tools][org-web-tools]] already owns the necessary Org integration and Pandoc conversion. [[https://github.com/alphapapa/org-protocol-capture-html][org-protocol-capture-html]] offers browser-selection capture, but its automatic readability route also uses EWW. [[https://github.com/dmgerman/browser-gt][browser-gt, formerly Browsel]] offers a browser extension, an Emacs WebSocket bridge, and dedicated page/ChatGPT commands; those capabilities have not been tested here. [[https://github.com/charlesroelli/org-board][org-board]] archives HTML and resources with wget rather than providing a better article extractor. None of these packages was installed for this comparison.

* Method and reproducibility
Tested Defuddle 0.19.6 with linkedom 0.18.14; Mozilla Readability 0.6.0 with jsdom 30.1.3; and the installed org-web-tools EWW extractor. All variants used the same saved source for each page, the existing Pandoc converter, and existing link/whitespace cleanup. Titles come from the source document because the initial Strobist extractor metadata returned a site slogan. Defuddle's async external fetching was disabled. Source text fragments, hrefs, image identities, captions, next links, chapter lists, and recipe structure were inspected; raw counts were only diagnostics.

The paragraph normalizer was checked on the real outputs for idempotence and preservation of the two Lighting 101 caption breaks. The complete selected pipeline passed on six pages plus the alternate Chrome snapshot of Lighting 101. After the cursor and section-hierarchy fixes, all 21 capture/Pandoc regression tests passed, including failed-fetch behavior, conversion-error diagnostics, the prefix override, missing-Node fallback, and repeated captures within sections. The three hierarchy tests also passed in running Emacs using in-memory copies of the real note.
