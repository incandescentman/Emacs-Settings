* What Is This?

This is a powerful Emacs configuration built on Spacemacs, designed for writing, note-taking, and knowledge management. It uses **literate programming** (Org files that generate Emacs Lisp code) and focuses heavily on org-mode and org-roam.

Key features:
- Smart clipboard integration for macOS (auto-cleans web content)
- Multiple org-roam databases (work vs. personal notes)
- Beautiful themes and fonts optimized for writing
- Extensive custom functions in [[file+emacs:/Users/jay/emacs/emacs-settings/shared-functions.org][shared-functions.org]]

* Installation

** First-Time Setup

1. *Clone the repository*
   #+BEGIN_SRC sh
   git clone git@github.com:incandescentman/Emacs-Settings.git ~/emacs/emacs-settings
   #+END_SRC

2. *Create the Spacemacs symlink*
   #+BEGIN_SRC sh
   ln -s ~/emacs/emacs-settings/spacemacs.d ~/.spacemacs.d
   #+END_SRC

   Note: This links Spacemacs' config directory to =spacemacs.d/= in this repo.

3. *Install external dependencies* (macOS)
   #+BEGIN_SRC sh
   brew install ripgrep pandoc hunspell enchant aspell
   #+END_SRC

4. *Launch Emacs*

   First launch takes 5-10 minutes while Spacemacs downloads packages. Let it complete.

5. *Reload configuration*

   After packages install, press =SPC f e R= (or =M-m f e R= in Emacs mode) to reload.

6. *Optional: Speed up startup*

   Byte-compile files for faster loading:
   #+BEGIN_SRC emacs-lisp
   (byte-recompile-directory "~/emacs/emacs-settings" 0)
   #+END_SRC

* Essential Features

** Smart Clipboard (Pasteboard)

The clipboard system automatically cleans up text from the web:

| Key     | Command                    | What It Does                                              |
|---------+----------------------------+-----------------------------------------------------------|
| =Cmd-v= | =pasteboard-paste-adaptive= | Auto-cleans in org/text, raw in code & fundamental buffers |
| =Cmd-c= | =pasteboard-copy-adaptive=  | Cleans formatting when copying from org, raw from code    |
| =Cmd-x= | =pasteboard-cut-adaptive=   | Smart cut with spacing/capitalization fixes               |

*Pro tip:* Add =C-u= prefix (=C-u Cmd-v=) to force verbatim paste/copy/cut, overriding smart detection.

*** Common Use Cases

*Copying from web to org-mode:*
1. Select text on a webpage
2. =Cmd-c= to copy
3. Switch to Emacs org buffer
4. =Cmd-v= to paste
5. Text arrives cleaned: proper headings, fixed quotes, nice formatting

*Pasting code exactly as-is:*
- Use =C-u Cmd-v= to paste without any modifications
- Fundamental or scratch buffers (`fundamental-mode`) already default to raw paste; switch to =text-mode= if you want cleaners there

** Web Page Capture

Two tools for getting web content into org-mode:

*** org-web-tools (from URL)

Fetches a URL and extracts the main article content using =eww-readable=.

| Command                                      | What It Does                                        |
|----------------------------------------------+-----------------------------------------------------|
| =jay/org-web-tools-read-url-as-org-clean=    | Opens page content in new org buffer                |
| =jay/org-web-tools-insert-web-page-as-entry-clean= | Inserts as org heading at point                |

*Usage:* Just have the page open in Chrome and run the command. No copying needed - it grabs the URL directly from Chrome's frontmost tab.

Falls back to: macOS clipboard → kill-ring → prompt

*** html2org-clipboard (from copied HTML)

Converts HTML you've already copied to org-mode.

| Keys                  | Command              | What It Does                                   |
|-----------------------+----------------------+------------------------------------------------|
| =C-v= / =C-s-v= / =M-s-v= | =html2org-clipboard= | Pastes clipboard HTML as clean org-mode text   |

*Usage:* Select content in browser, copy (Cmd-C), then run =html2org-clipboard=.

Notes:
- Best for copied fragments, selected passages, and ChatGPT output already on the clipboard.
- For full article pages, especially sites like Substack, use =jay/org-web-tools-read-url-as-org-clean= instead. URL capture is much better at extracting the main article and skipping page chrome, comments, and footer cruft.

*** When to Use Which

- *org-web-tools*: Capture an entire article from a URL (auto-extracts main content)
- *html2org-clipboard*: Paste a specific selection you copied (ChatGPT output, partial page)

** Editing Browser Textareas in Emacs (GhostText)

Any time you find yourself writing more than a sentence into a browser textarea — Substack drafts, GitHub PR descriptions, social compose boxes, ChatGPT — edit it in Emacs instead via =atomic-chrome= + the GhostText Chrome extension.

Workflow:
1. Click into the textarea in Chrome
2. Click the GhostText icon in the Chrome toolbar
3. An Emacs frame opens with the contents in =org-mode=
4. Type — the browser auto-syncs both ways
5. Kill the buffer (=C-x k=) to disconnect

Notes:
- Works on any =<textarea>= or contenteditable field, not just specific sites
- Buffer opens in =org-mode= by default, so you get all your prose tools
- The Chrome extension must be installed: GhostText (search the Chrome Web Store)
- Emacs side is wired up via =atomic-chrome= (added 2026-04 in commit =e4f42654=)

Both tools automatically strip:
- Base64-encoded images
- Social share buttons (Facebook, Twitter, LinkedIn, etc.)
- View counts (=//6,728=)
- Empty icon links
- Capture timestamps (by default)
- =:website:= tags

All paste methods (including =pasteboard-paste-adaptive=) convert bold lines that look like headings into actual org headings:
- =*1. Classic Unalome:*= → =*** 1. Classic Unalome:=
- =*Heading*= → =*** Heading=

** Text Manipulation

| Key         | Command                        | What It Does                                    |
|-------------+--------------------------------+-------------------------------------------------|
| =Cmd-k d l= | =double-line-breaks-in-region= | Double all single line breaks in selected region |

=double-line-breaks-in-region= is useful for converting single-spaced text to double-spaced paragraphs. It normalizes line endings, collapses 3+ newlines to exactly 2, and only doubles single newlines (leaving existing paragraph breaks unchanged).

*** Transcript Cleanup

Use =M-x whittle= for safe everyday cleanup and =M-x whittle-transcript= when you're cleaning raw spoken transcripts.

| Command                | Best For                                  | What It Does |
|------------------------+-------------------------------------------+--------------|
| =whittle=              | Light cleanup of prose or lightly messy text | Removes safer fillers, collapses duplicated words, and fixes punctuation spacing without being too aggressive |
| =whittle-transcript=   | Raw transcripts, dictated text, pasted captions | Joins mid-sentence line breaks, removes filler chains, strips sentence-edge fillers, collapses false starts, normalizes punctuation, and fixes capitalization |

Both commands work on the active region if one is selected, otherwise on the whole buffer.

*Conservative =whittle=*
- Safe defaults for ordinary prose
- Keeps legitimate phrases like =I like cats=
- Cleans repeated words like =hello hello=
- Fixes spacing such as =Hello , world= to =Hello, world=

*Aggressive =whittle-transcript=*
- Designed for transcript junk rather than polished prose
- Removes filler chains like =um, uh, you know,=
- Removes sentence-edge fillers like =Like,= at the start of a sentence
- Collapses false starts like =I was I was thinking= or =we were we were ready=
- Joins awkward single newlines when the sentence clearly continues
- Capitalizes sentence starts and lone =i=
- Preserves some intentional repeats such as =go go= and =bye bye=

*Example*

Input:
#+begin_example
Um, the dog ran. well, i think
this is fine
#+end_example

After =whittle-transcript=:
#+begin_example
The dog ran. I think this is fine
#+end_example

** Table Export Behavior (2026-02)

For =elegant-helvetica=, =elegant-garamond=, and =beautiful-racket= classes:

- Default: plain Org tables are auto-converted to wrapping =tabularx= output.
- Wrapped output uses left-aligned wrapping columns and light booktabs rules:
  - =\toprule=
  - =\midrule=
  - =\bottomrule=
- Per-table opt-out:

#+BEGIN_EXAMPLE
#+ATTR_LATEX: :wrap nil
| Col A | Col B |
|-------+-------|
| ...   | ...   |
#+END_EXAMPLE

With =:wrap nil=, export stays native =tabular= for that table.

Implementation detail:
- Shared helper: [[file+emacs:/Users/jay/emacs/emacs-settings/latex-templates/jay-latex-table-wrap.el][latex-templates/jay-latex-table-wrap.el]]
- Each class file registers itself with the shared wrapper.

** Tabularray Classes (Opt-In, Same Look by Design)

Additional opt-in classes are available:
- =elegant-helvetica-tabularray=
- =elegant-garamond-tabularray=
- =beautiful-racket-tabularray=

These are intended to preserve the same visual style as the classic classes for normal proposal tables. In side-by-side exports, differences should usually be small or invisible at normal reading distance.

Use this rule of thumb:
- Keep classic classes for normal production work.
- Switch to a tabularray class when a specific table misbehaves (pagination, overflow edge cases, or brittle conversion behavior).

Why this exists:
- The tabularray path is mainly an internal robustness/maintainability upgrade (modern table engine, cleaner conversion pipeline), not a redesign.
- Think of it as an opt-in reliability path, not a mandatory style change.

- If you edit a LaTeX template file and export in the same Emacs session, reload the template definitions first with =M-x jay-load-latex= or restart Emacs; otherwise export can keep using stale class definitions already loaded in memory.

** PDF Filename From =#+TITLE:=

When you export an Org file to PDF, the output PDF is renamed in place to use =#+TITLE:= as its basename. For example, =20260401-paul-follow-up-answers-email-draft.org= with =#+TITLE: Answers to follow-up questions= exports to =Answers to follow-up questions.pdf= in the same directory, not =20260401-paul-follow-up-answers-email-draft.pdf=.

Behavior:
- Spaces are preserved (readable as an email attachment).
- Filesystem-hostile characters such as slash, backslash, colon, asterisk, question mark, double quote, less-than, greater-than, pipe, and control characters are stripped.
- Runs of whitespace collapse to a single space; trailing periods are trimmed.
- Existing files with the target name are overwritten silently.
- If the Org buffer has no =#+TITLE:=, the original basename is kept as a fallback.
- PDF export only — HTML/ODT/DOCX output is not renamed.

Implemented as =:filter-return= advice on =org-latex-export-to-pdf= in [[file+emacs:/Users/jay/emacs/emacs-settings/org-export.org][org-export.org]].

** Contract Signature Lines

When writing contracts for LaTeX/PDF export, do not rely on long underscore runs as the primary source form for signature blanks. In this config's Org→LaTeX export path, underscores already have underline semantics, so punctuation-based signature lines are the wrong primitive.

Best practice:

#+BEGIN_EXAMPLE
#+filetags: :contract:
#+MACRO: sigline @@latex:\rule{2.75in}{0.4pt}@@

Signature: {{{sigline}}}
Date: {{{sigline}}}
#+END_EXAMPLE

Notes:
- Prefer the =sigline= macro form. It is explicit in the Org source and exports cleanly.
- If a contract file is tagged =:contract:=, LaTeX export will also auto-repair simple lines like =Signature: ______= and =Date: ______= into real =\rule{...}= signature blanks in the temporary export buffer.
- For more complex layouts (multiple signers, signature/date columns, witness blocks), use a small =#+begin_export latex= block with =tabular= or =minipage= instead of trying to build the layout out of punctuation.

** Emacs won't start / error on startup

The config is complex. To debug:
1. Check =*Messages*= buffer for errors
2. Look for mentions of missing files or functions
3. Try temporarily renaming =~/.spacemacs.d= to test vanilla Spacemacs

2. Restart Emacs (it will re-download everything)

** Slow startup

1. Byte-compile files:
   #+BEGIN_SRC emacs-lisp

   #+END_SRC

2. Check [[file+emacs:/Users/jay/emacs/emacs-settings/spacemacs.d/init.el][spacemacs.d/init.el]] for unused layers (comment them out)

3. Profile startup with =emacs --timed-requires=

** "File has changed on disk" errors with Dropbox

Already fixed as of 2025-10-11. File watching is disabled for cloud storage folders (Dropbox, iCloud, OneDrive). Emacs now polls these folders instead.

** Org-roam database errors

Rebuild the database:
#+BEGIN_SRC emacs-lisp
(org-roam-db-sync)
#+END_SRC

Or delete and rebuild:
#+BEGIN_SRC sh
rm ~/Dropbox/roam/org-roam.db
#+END_SRC

Then in Emacs: =M-x org-roam-db-sync=

** =s-R= (=fasd-find-file=) doesn't look recent-first

Quick checks:
1. Confirm the file is in fasd:
   #+BEGIN_SRC sh
   fasd -ltR | head -n 25
   #+END_SRC
2. Confirm fasd's active DB file (fasd reads =_FASD_DATA=; if unset, it typically uses =/Users/jay/.cache/fasd=):
   #+BEGIN_SRC sh
   echo "${_FASD_DATA:-/Users/jay/.cache/fasd}"
   ls -la "${_FASD_DATA:-/Users/jay/.cache/fasd}"
   #+END_SRC
3. If shell output is correct but Emacs ordering looks wrong, verify [[file+emacs:/Users/jay/emacs/emacs-settings/shared-functions.org][shared-functions.org]] uses completion metadata in =fasd-find-file=:
   - =(display-sort-function . identity)=
   - =(cycle-sort-function . identity)=

That metadata prevents Vertico from re-sorting fasd's already-sorted candidate list.

Workflow:
1. Use Emacs normally; =keyfreq= silently records usage.
2. Run =M-x my/keybinding-dump= then =M-x my/keybinding-merge= to update the reference.
3. Add notes to [[file+emacs:/Users/jay/emacs/emacs-settings/docs/keybinding-annotations.org][keybinding-annotations.org]] — they survive regeneration.
4. After usage data accumulates, run =M-x my/keybinding-frequency-report= to find optimization opportunities.
